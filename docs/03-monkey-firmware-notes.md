# 03 — Monkey 固件设备发现与操作约定（龙旗产测固件）

> 来源：现场实测总结（2026-09）。适用 **Monkey 固件**（产测）；量产固件广播按需开启，不在本约定范围。

## 1. 扫描发现（怎么找到手表）

Monkey 固件开机后自动拉起 BLE 广播，广播包内容：

```
02 01 06                          Flags
03 03 02 38                       Complete 16-bit Service UUID = 0x3802
09 16 02 38 XX XX XX XX XX XX     Service Data (UUID 0x3802) + 6 字节标识
```

- **扫描过滤条件**：广播 AD type 0x03 中包含 16-bit UUID `0x3802`
- 广播参数：ADV_IND 可连接、间隔 30ms、public 地址类型、发射功率 -10dBm
- **广播不带设备名**（scan response 为空），不要按名称过滤

注意事项：

- Service Data 中的 6 字节是 MAC 十六进制字符串**前 3 位 + 后 3 位的 ASCII 码**，不是原始 MAC。
  例如 MAC `8C:88:2B:62:05:3F` → payload 为字符 `'8','c','8','5','3','f'`。
  **要区分设备请直接用广播源地址（手表蓝牙 MAC）匹配，不要解析这 6 字节**
- `0x3802` 是龙旗设备通用 UUID，**多台设备同场压测时必须按 MAC 地址区分**

## 2. GATT 服务（连接后用什么）

| 项 | 值 |
|---|---|
| Service UUID | `1b7e8251-2877-41c3-b46e-cf057c562023` |
| TX/RX 特征 UUID | `8ac32d3f-5cb9-4d44-bec2-ee689169f626` |
| 特征属性 | Write No Response（手机→表）+ Notify（表→手机） |
| 前置动作 | 连接后先写 CCCD 打开 Notify |
| 配对/鉴权 | 无。不加密、不绑定、不需要小米账号，直接连接即可 |

## 3. 数据帧格式（写 TX/RX 特征）

```
字节0: Service ID (ASCII)   '0'(0x30)=命令通道   '3'(0x33)=文件传输通道
字节1: Command ID (ASCII)   见下表
字节2~: payload (ASCII 字符串)
```

命令通道（SID '0'）的 Command ID：

| CID | 含义 |
|-----|------|
| `'0'` | AT 命令（最常用） |
| `'1'` | FI |
| `'2'` | XR AT |
| `'6'` | 导出文件 |
| `'7'` | NFC |

发 AT 命令 = `'0' + '0' + "AT命令字符串"`，例如 `"00AT^USERDEBUG=ON"`。
AT 执行结果通过 Notify 异步返回。

**单次写入受 ATT MTU 限制（默认有效载荷 20 字节）。长命令请先协商 MTU 或分包发送**；
文件传输走 SID '3' 的协商流程（见 `02-ota-file-transfer.md` 通道 B）。

## 4. 行为约定（压测脚本需要处理的边界）

- **反复重连**：每次断连后手表立即重开广播，脚本可循环 "连接 → 操作 → 断开 → 重连"
- **灭屏边界**：手表灭屏进入低功耗后**蓝牙整体下电**，扫不到也连不上；亮屏/唤醒后广播自动恢复。
  脚本连不上时应先唤醒设备或等待，**不要直接判定设备故障**
- **固件范围**：lc_proto 广播常开只在 Monkey 固件生效；量产固件该广播是按需的（如设置页二维码），
  不要拿量产机验证
